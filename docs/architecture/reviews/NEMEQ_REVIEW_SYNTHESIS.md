## 1. Self-contained: принцип сформулирован неверно

Оба ревьюера независимо указали одно и то же: **декларация «нет внешних зависимостей» ложна**, пока не поставляется интерпретатор. Колёса `cp312` + manylinux = жёсткий лок на ABI и glibc.

Разделить на два утверждения (Opus):
- (а) **нет сетевых и пакетных зависимостей** — ни pip, ни ensurepip, ни venv, ни реестров;
- (б) **хостовые предпосылки объявлены и проверяются**: `python3 >=3.12,<3.13`, `x86_64`, glibc ≥ N, локальная ФС.

Для Rust-этапа зафиксировать target triple `x86_64-unknown-linux-musl`, иначе «статический бинарь» унаследует ту же glibc-зависимость.

Gemini добавляет технический барьер: принудительно чистить `sys.path` на старте, оставляя только `lib/pydeps` — если импорт пошёл не оттуда, приложение падает.
Критерий: в рантайме `sys.path` не содержит `/usr/lib/python3/dist-packages` и `~/.local/lib/...`.

**Колёса как zip ≠ установка** (Opus): не обрабатываются `.pth`, `*.data/{scripts,purelib}`, `entry_points`, не проверяется `RECORD`. Решение — распаковка с проверкой sha256 по `deps.lock`, подключение через `site.addsitedir()`, а не `PYTHONPATH`; `nqctl deps verify`.

**`lib/` объявлен immutable, но Python пишет туда `__pycache__`.** Решение: `PYTHONPYCACHEPREFIX` в mutable-часть, `chmod -R a-w lib` при install, предкомпилированные `.pyc` в поставке.

## 2. Раскладка

**`state/state/`** — переименовать mutable-корень в `var/` (Opus). Тогда `/var/nemeq X → $NEMEQ_HOME/var/X` для любого X, без исключений, и слово `state` остаётся только за старым смыслом.

**Нет `tmp/`** — атомарная запись через tmp+rename требует, чтобы staging был на том же устройстве. Иначе `EXDEV` или неатомарная подмена. Добавить `var/tmp/` (0700) + `doctor` сверяет `st_dev`.

**Нет манифеста установки** — `lib/INSTALL.json`: `layout_version`, `nemeq_version`, `schema_version`, `deps_lock_sha256`, `platform_tag`, `build_id`. Код отказывается открывать стор со схемой новее своей.

**`run/` с overlay противоречит §0.1** — overlay это `mount()`, то есть root. Либо copy-on-write каталог `var/overlay/`, либо это уровень (в) и уезжает из документа.

**Unix-сокеты в `run/` упираются в 108 байт** (`sun_path`). Длинный HOME → `AF_UNIX path too long` на старте. Валидация в `install`/`doctor`, порог 100.

**Стор в `$HOME` и квоты** — «убежавший» WAL заполнит домашний раздел. `max_state_bytes` + soft-лимит на 80%, `doctor` проверяет права и место, бэкапы `$HOME` исключают `var/store`.

**Три вещи ломают контракт SDD v0.4 §4**, хотя сама структура `epishu/<id>/` сохраняется:
1. вложение `state/state`, если код считает пути от глубины;
2. **абсолютные пути внутри атомов/трейсов** — после смены корня указывают в никуда; `fsck` должен их находить;
3. ФС: `$HOME` может быть NFS/overlay, где `flock`/`rename` не дают гарантий TEXTSTORE → `doctor` проверяет `stat -f`, NFS запрещён.

## 3. Резолвинг

**Цепочек не одна, а три** (Opus). §7 сохраняет `--state-root`, §4 вводит `--home` — взаимодействие не определено:

```
home:  --home       > NEMEQ_HOME     > $HOME/.nemeq
var:   --state-root > NEMEQ_VAR_ROOT > <home>/var
store: --store      > NEMEQ_STORE    > <var>/store
```

Правила: все переопределения обязательны абсолютными (относительный → ошибка, не «приведём от CWD»); `--state-root`/`--store` вне `<home>` только с `--allow-outside-home`; при env-переопределении печатать `source=env(NEMEQ_VAR_ROOT)` в `nqctl status`.

**`$HOME` обязателен.** Отсутствует/пуст → отказ с кодом 2, **никогда** не фоллбэчить на CWD или `/`. Иначе нарушается критерий §8.5.

**`%h` в systemd — ловушка** (B6): в системном юните `%h` это HOME менеджера (root), а не `User=beta`. Генерировать абсолютный путь через `nqctl install-unit`, `%h` не использовать.

**Gemini:** `install` не должен создавать структуру неявно; `apiserver` без `init` обязан падать с `NemeqNotInitialized`, а не плодить каталоги.

## 4. Инстансы

**Оба ревьюера против дефолта «профиль в одном HOME» в текущей формулировке** — но по разным причинам и с разными выводами:

- **Gemini:** убрать (а) совсем, дефолт — отдельный HOME. Общий `lib/` = бомба при обновлении: обновился `pydeps` — упал второй инстанс.
- **Opus:** дефолт — профиль, но правильно разделив понятия: `NEMEQ_HOME` = префикс (`bin/ lib/`), `NEMEQ_INSTANCE` = имя под `$NEMEQ_HOME/instances/<name>/` (`config/ state/ logs/ run/`). Тогда `lib/` действительно общий, а изоляция данных доказывается тестом, не раздельностью каталогов.

**Мой выбор: вариант Opus.** Причина: отдельный HOME — это N копий кода, N процедур обновления и неизбежный version skew, тогда как изоляция данных достигается структурой каталогов и доказывается тестом (разные inode, 404 на чужой объект). Правило выбора записать механически: «разные UID или разные версии — разные HOME, иначе профили».

**Чего нет в §5 вообще** (Opus):
- `home_id` (UUID) в `instance.toml` и метаданных стора, сверка при старте;
- порт по умолчанию и `run/instance.json` с фактическим портом; `EADDRINUSE` → код 3 с именем виновника;
- **flock**: строго `$NEMEQ_HOME/run/store.lock`, `O_NOFOLLOW`, 0600 — иначе инстансы снова сцепятся, плюс symlink-атака в world-writable каталоге;
- user-unit `~/.config/systemd/user/` вместо системного `/etc/systemd/system` (root = нарушение §0.1);
- жизненный цикл `instance create|list|status|destroy`, права 0700/0600, umask 077.

## 5. Миграция — самый слабый раздел

**TOCTOU** (Opus): проверили лок, отпустили, начали копировать — писатель мог появиться. Решение: требовать остановленный сервис, отказ с кодом 2 и текстом «stop nemeq-<i> first». `--force` не вводить.

**Неатомарность**: крах посреди копии оставляет полу-стор, который fsck примет (rev совпадает на префиксе). Копировать в `state.migrating-<ts>/`, fsck по staged, затем `rename()`, маркер `MIGRATION_INCOMPLETE`.

**`rev`+`last_hash` — недостаточная идентичность**: это голова, а не стор. Ввести `store_digest = sha256` по `(epishu_id, rev, last_hash, atom_count, wal_segments_crc)` + `anchor_hash`.

**`chown` обязателен** (Gemini + Opus): root→user меняет владельца; «сохранение прав» даст недоступный стор. После копирования `chown -R`, снятие setuid/setgid, отказ при файлах третьих uid.

**Symlink не упомянуты**: абсолютные ссылки внутрь `/var/nemeq` станут висячими, разыменование вытащит данные за пределы HOME. Копировать как ссылки, абсолютные — в отчёт и отказ, `--rewrite-links` для переписывания префикса.

**Anchor и незавершённые транзакции не покрыты вовсе**: anchor не назван ни в списке копируемого, ни в сверке. Грязный WAL: по умолчанию отказ (код 6), `--recover` реплеит в staged-копию, rev сравнивается **после** реплея.

**Удаление источника по умолчанию — риск потери данных.** Дефолт: **не удалять**. `--purge-source` только после fsck + старта сервиса + health ok + write/read roundtrip.

**Нет карты путей и обработки неизвестных записей**: `--dry-run` печатает отображение и **падает** на записи без правила. Плюс старый `/etc/systemd/system/nemeq.service` после миграции остаётся и поднимает инстанс на удалённых путях.

## 6. Критерии приёмки — половина не проверяет ничего

- **§8.1 вакуумный** (B1): `grep` без `-E` ищет литерал `|`. Заменить на `git grep -nE` + архитектурный тест: пути допустимы только в одном модуле `massaru/legacy.py`.
- **§8.2 доказывает меньше нужного**: 404 получается и при баге маршрутизации, и при пустом сторе. Нужен тест: один id в обоих сторах с **разным** содержимым, разные inode, и проверка что тест не тавтологичен (подмена HOME → падает).
- **§8.3**: health обязан отдавать `{instance, home_id, rev, last_hash, fsck}`; сравнивать до/после restart.
- **§8.5 непроверяем**: «вне HOME не создаётся каталогов» — чем мерить? Нужен `strace -f -e trace=openat,mkdir` с allow-list.
- **§8.6**: переписать под digest + добавить блок негативных сценариев (коды 2/4/6/7). Иначе §6 может быть не реализован, а §8 будет зелёным.
- **Чего нет совсем**: работа без sudo; идемпотентность install; `uninstall --purge`; гонка старта (два процесса → один жив); HOME с пробелом и не-ASCII; поведение на NFS; `doctor --json` как артефакт приёмки.

**Gemini добавляет:** проверка `stat` — UID всех файлов в `$NEMEQ_HOME` должен совпадать с текущим пользователем.

| Вопрос | Решение | Кто |
|---|---|---|
| 1. Профиль vs отдельный HOME | Дефолт — профиль, но через `NEMEQ_INSTANCE` + `instances/<name>/`, с общим `lib/`. Отдельный HOME — только при разных UID/версиях | Opus (принято) |
