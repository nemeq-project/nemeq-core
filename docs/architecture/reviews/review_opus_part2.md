## §5 — Три уровня инстансов

**З-5.1. §5(а) противоречит §4.** `--home ~/.nemeq/profiles/alpha` по определению §4 — это корень, в котором лежат `bin/`, `lib/`, `state/`. Значит профиль тащит свой `lib/`, и заявленная экономия 30 МБ фиктивна: (а) в нынешней формулировке — это (б) с вложенным путём.
*Предложение:* развести два понятия. `NEMEQ_HOME` — префикс (содержит `bin/`, `lib/`); `NEMEQ_INSTANCE`/`--instance` — имя под `$NEMEQ_HOME/instances/<name>/` (там `config/ state/ logs/ run/`). Инстанс `default` остаётся плоским (`state/` прямо в HOME) для совместимости с уже развёрнутыми alpha/beta. В §4 добавить `--instance`, в §3 — ветку `instances/<name>/`.
*Критерий:* `nqctl --home A --instance alpha` и `... --instance beta` — в `A/lib` один экземпляр кода (`find A/lib -maxdepth 1 | wc -l` не растёт), `du -sh A` после второго инстанса растёт менее чем на объём данных; `nqctl instance list` показывает оба.

**З-5.2. §5 не задаёт идентичность инстанса и порты.** В `instance.toml` есть имя и порт, но ничто не связывает стор с HOME: скопированный HOME даёт два инстанса с одним именем и портом, и `443`/`8448`-коллизия обнаруживается только падением bind. Дефолт порта не определён.
*Предложение:* при install генерировать `home_id` (UUID) в `instance.toml` **и** в метаданных стора; при старте — сверка, при расхождении отказ с кодом 5. Порт по умолчанию — `0` (эфемерный) либо явный в `instance.toml`; фактический порт писать в `run/instance.json` (`{name, home_id, pid, port, started_at}`). При `EADDRINUSE` — код 3 и сообщение с именем инстанса, который держит порт (поиск по `instances/*/config/instance.toml` и `run/instance.json`).
*Критерий:* два инстанса с одинаковым портом — второй завершается non-zero, ничего не пишет в стор, сообщение называет виновника; `cat run/instance.json` содержит живой pid и реальный порт.

**З-5.3. §5 молчит про flock — а это корень исходной проблемы (§1.1).** Если лок окажется по фиксированному пути (`/tmp/nemeq.lock`) или по пути стора, инстансы снова сцепятся. Плюс lock-файл в world-writable каталоге — поверхность для symlink-атаки.
*Предложение:* лок строго `$NEMEQ_HOME/run/store.lock`, `open(O_RDWR|O_CREAT|O_NOFOLLOW, 0600)`, `flock(LOCK_EX|LOCK_NB)`; при занятости — код 4 и «store busy: pid N» из файла. Запретить любые фиксированные пути вне HOME (§7 — добавить в список правок место, где лок открывается).
*Критерий:* второй процесс на том же HOME падает за <1 с с кодом 4 и читаемым сообщением; на разных HOME — оба живы; `strace` показывает ровно один `openat` lock-файла, путь внутри HOME.

**З-5.4. §5 требует «имя unit-файла с инстансом», но не говорит, где unit лежит и от чьего имени.** Системный `/etc/systemd/system` требует root — это прямое нарушение §0.1 и §1.2.
*Предложение:* дефолт — user-unit `~/.config/systemd/user/nemeq-<instance>.service`, `systemctl --user enable --now`; системные unit — только для уровня (в). В шаблоне обязательно: `Environment=NEMEQ_HOME=%h/.nemeq`, `Environment=NEMEQ_INSTANCE=<name>`, `WorkingDirectory=%h`, `ExecStart=%h/.nemeq/bin/nqctl serve`, `Restart=on-failure`, `KillMode=mixed`, `TimeoutStopSec=20`. Дешёвая часть уровня (в), которую стоит взять сейчас: `NoNewPrivileges=yes`, `PrivateTmp=yes`, `ProtectSystem=strict`, `ReadWritePaths=%h/.nemeq`, `ProtectHome=read-only` + исключение для HOME инстанса.
*Критерий:* установка и `systemctl --user start` от непривилегированного пользователя без sudo; `systemd-analyze verify` на сгенерированном unit; в `systemctl --user show -p Environment` видны оба `Environment=`.

**З-5.5. §5 не описывает жизненный цикл и права.** Есть только «поддержать (а) и (б)». Нет create/list/status/destroy, нет umask, нет владельца каталогов — а §6 потом требует «сохранения прав», которых неоткуда взять.
*Предложение:* `nqctl instance create|list|status|destroy`; `create` делает HOME/инстанс с `0700`, `config/instance.toml` `0600` (там могут быть токены), `run/` `0700`, umask `077` на весь процесс; `destroy` требует остановленного сервиса, берёт лок и удаляет только `state/ config/ logs/ run/` инстанса, `lib/` не трогает.
*Критерий:* `stat -c %a` на HOME/config/run = 700/600/700; `instance destroy` при живом сервисе отказывает с кодом 4; после destroy `lib/` на месте, `nqctl instance list` пуст.

## §6 — Миграция

**З-6.1. Проверка «источник не занят писателем» — TOCTOU.** Проверили, отпустили лок, начали копировать — писатель мог появиться между шагами. Также не сказано, что делать при занятом сторе, и не проверяется **целевой** HOME.
*Предложение:* либо держать эксклюзивный лок источника на всё время копирования, либо (проще и честнее) требовать остановленный сервис и отказывать с кодом 2 и текстом «stop nemeq-<i> first»; `--force` не вводить. Перед копированием — лок и проверка target: непустой `state/` → отказ, если не указан `--merge`.
*Критерий:* негативный тест: при запущенном сервисе `migrate` завершается кодом 2 и не создаёт файлов в target; при непустом target — код 2; повторный запуск после остановки проходит.

**З-6.2. Копирование неатомарно.** Крах посреди копии оставляет полу-стор, который fsck может принять (rev совпадает на префиксе), и следующий `migrate` решит, что target уже готов.
*Предложение:* копировать в `state.migrating-<ts>/`, fsck гонять по staged-каталогу, затем `rename()` в `state/`; при ошибке staged удаляется, маркер `MIGRATION_INCOMPLETE` в `run/` до успешного rename.
*Критерий:* kill -9 на 50% копирования → target не содержит `state/`, есть только `state.migrating-*` и маркер; повторный запуск начинается с нуля, а не «продолжает».

**З-6.3. Сверка `rev` + `last_hash` — недостаточная идентичность.** Это голова, а не стор: не покрывает число атомов, число WAL-сегментов, `paqidutu`/`view`, anchor.
*Предложение:* ввести `store_digest = sha256` по отсортированным `(epishu_id, rev, last_hash, atom_count, wal_segments_crc)` + `anchor_hash`; сверять digest, а не пару. Печатать и складывать в `run/migration-report.json`.
*Критерий:* отчёт содержит digest источника и цели, они равны; тест с подменой одного байта в `atoms` целевого стора после копирования → digest расходится, миграция не считается успешной.

**З-6.4. Права и владелец.** §6 говорит «с сохранением прав», но миграция `/var/nemeq` (root) в `~/.nemeq` (пользователь) меняет владельца — простое сохранение прав даст стор, недоступный для записи.
*Предложение:* после копирования — `chown -R <target uid>:<gid>`, снятие setuid/setgid битов, отказ (не «молчаливое исправление»), если в источнике есть файлы, принадлежащие третьим uid.
*Критерий:* `find target/state ! -user $(id -u)` пусто; `find target/state -perm /6000` пусто; тест-фикстура с файлом root:wheel в источнике → migrate отказывает с перечислением файлов.

**З-6.5. Symlink не упомянуты.** Абсолютные ссылки внутрь `/var/nemeq` после переезда станут висячими; разыменование при копировании вытащит данные за пределы HOME.
*Предложение:* копировать ссылки как ссылки (без dereference), абсолютные ссылки, чей target вне источника, — в отчёт и отказ по умолчанию (`--rewrite-links` для переписывания префикса); симлинк, ведущий наружу источника, — всегда отказ.
*Критерий:* фикстура с `state/x -> /var/nemeq/state/y` → migrate отказывает, путь назван в отчёте; с относительной ссылкой внутри стора — копия сохраняет `lrwxrwxrwx`, `readlink` идентичен.

**З-6.6. Anchor и незавершённые транзакции не покрыты вовсе.** Anchor не назван ни в списке копируемого (шаг 2), ни в сверке (шаг 3). Грязный WAL-хвост (краш писателя) fsck либо «починит», либо проигнорирует — политика не задана.
*Предложение:* добавить в шаг 2 явный перечень: `anchor*`, `wal/`, `paqidutu/`, `view/`, `zikru-*`, `observability_log`. fsck источника — в strict-режиме; при непустом хвосте WAL: по умолчанию отказ с кодом 6 и предложением `--recover`, который реплеит WAL в staged-копию, после чего `rev` сравнивается **после** реплея на обеих сторонах.
*Критерий:* фикстура с оборванной транзакцией → код 6 и перечень незавершённых записей; с `--recover` — rev совпадает, отчёт фиксирует число реплеенных записей и что источник не изменялся (mtime/размер до и после).

**З-6.7. Удаление источника по умолчанию — риск потери данных, а `--keep` — плохой дефолт для миграции.**
*Предложение:* дефолт — **не удалять**; `--purge-source` — опционально и только после: успешного fsck + реального старта сервиса на target + health ok + одного write/read roundtrip. В отчёт писать команду удаления источника, чтобы оператор выполнил её сам.
*Критерий:* после `migrate` без флага источник на месте; с `--purge-source`, но при падении сервиса на target — источник на месте, код non-zero.

**З-6.8. Нет карты путей «старое → новое» и нет обработки неизвестных записей; не учтён version skew и старый unit.** В старой раскладке `apiserver` — это стор, в новой `state/store`, а `epishu/` в §6 копируется как «top-level», хотя в §3 оно внутри `state/`; заодно появляется коллизия `state/state`. `/etc/systemd/system/nemeq.service` после миграции остаётся и поднимает инстанс на удалённых путях. Плюс fsck старого кода (`/opt/nemeq`) и нового (`lib/nemeq-core`) — разные версии.
*Предложение:* явная таблица соответствия в §6 (по каждому элементу старого корня) + `nqctl migrate --dry-run`, который печатает полное отображение и **падает** на любой записи, для которой нет правила. В отчёт писать `format_version` и версию nemeq-core источника и цели; отказ, если `format_version` вне поддерживаемого диапазона. Отдельным шагом — `systemctl disable --now nemeq.service` + печать новых unit-команд.
*Критерий:* `--dry-run` на фикстуре со «лишним» файлом `junk.bin` в корне — код 7 и имя файла; на чистой фикстуре — полная таблица, ни одного шага «прочее/остальное»; в отчёте есть `source_version`, `target_version`, `format_version`.

## §8 — Критерии приёмки

**З-8.1. Критерий 1 не проверяет ничего.** `grep -rn "/var/nemeq|/opt/nemeq|/run/nemeq"` без `-E` ищет литерал с вертикальными чертами — не находится никогда, критерий проходит вакуумно. Плюс `--include=*.py` не покрывает unit-шаблоны, shell, toml, docs.
*Предложение:* `git grep -nE '/(var|opt|run)/nemeq' -- ':!docs' ':!tests/fixtures'` **и** архитектурный тест: строки допустимы только в одном модуле (`massaru/legacy.py`), остальной код берёт пути через `resolve_home()`.
*Критерий:* тест падает, если добавить `/var/nemeq` в любой файл вне `legacy.py`; на текущем дереве — зелёный; отдельно проверено, что при подстановке «плохого» пути в `legacy.py` тест остаётся зелёным (allow-list работает).

**З-8.2. Критерий 2 доказывает меньше, чем нужно.** 404 на чужой объект получается и при баге маршрутизации, и при пустом сторе beta. Ручная проверка из §9 не заменяет приёмочный тест.
*Предложение:* автотест: один и тот же id записан в alpha и beta с **разным** содержимым, оба читаются независимо и корректно; пути файлов в двух сторах не пересекаются (`realpath` disjoint, разные inode); второй старт на том же HOME → код 4.
*Критерий:* тест в `tests/p0`, зелёный в CI; при подмене `NEMEQ_HOME` beta на alpha — тест падает (проверка, что тест не тавтологичен).

**З-8.3. Критерий 3 неоднозначен и слаб.** Не сказано, `systemctl` или `systemctl --user`; «health ok» может отдаваться и без открытого стора.
*Предложение:* health-эндпоинт обязан возвращать `{instance, home_id, rev, last_hash, fsck: clean}`; критерий: до и после `restart` — `rev` не убывает, `last_hash` совпадает, `instance`/`home_id` те же; проверка от имени того пользователя, который владеет HOME.
*Критерий:* скрипт сравнения двух JSON-снимков health; при остановленном сторе health отдаёт non-200 (проверить, что критерий это ловит).

**З-8.4. Критерий 5 непроверяем в текущей формулировке.** «Вне $NEMEQ_HOME не создаётся ни одного каталога» — чем измерять? И он не ловит реальную проблему: Python пишет `__pycache__` в `lib/`, что ломает заявленную иммутабельность `lib/` и падает на ro-mount.
*Предложение:* метод: `strace -f -e trace=openat,mkdir,mkdirat,bind` на install+первый запуск, фильтр по `O_CREAT|O_WRONLY` вне HOME; допустимые исключения перечислить явно (`/dev/null`, `/proc/self`, сокет systemd, `$XDG_RUNTIME_DIR` — если разрешён, то разрешён осознанно). Отдельным пунктом: `PYTHONDONTWRITEBYTECODE=1` + предкомпилированные `.pyc` в поставке, `lib/` монтируется ro.
*Критерий:* вывод strace не содержит create/write вне allow-list; `find lib -newer lib/.stamp` пусто после 10 запусков; `chmod -R a-w lib` не ломает старт.

**З-8.5. Критерий 6 не доказывает отсутствие сети.** «Сеть недоступна» — это про машину, а не про поведение поставки: код может пытаться и таймаутить (сейчас так и есть по описанию).
*Предложение:* прогон в `unshare -n` **и** прогон с сетью с `strace -e connect,sendto` — ноль попыток наружу. Проверка ABI: ни одного колеса с тегом, несовместимым с поставляемым интерпретатором; smoke-импорт каждого из 11 пакетов в чистом окружении (`python -S`? нет — с явным `PYTHONPATH=lib/pydeps`).
*Критерий:* лог `strace` — ноль `connect` к non-unix; `pip`/`ensurepip` отсутствуют в PATH тестового окружения (проверяется в самом тесте); `for m in $(cat deps.txt); do python -c "import $m"; done` — 0.

**З-8.6. Критерий 4 нужно переписать под §6.** `rev`+`last_hash` — см. З-6.3. И нет ни одного негативного критерия (грязный стор, symlink, занятый стор, крах посреди копии) — то есть §6 может быть не реализован, а §8 будет зелёным.
*Предложение:* заменить на сравнение `store_digest`; добавить в §8 явный блок «негативные сценарии миграции» с кодами возврата 2/4/6/7.
*Критерий:* каждый негативный сценарий — отдельный тест с ожидаемым кодом и ожидаемым состоянием target.

**З-8.7. Чего в §8 нет вообще** (и без чего приёмка формально пройдёт на сломанной поставке):
*Предложение:* добавить критерии — (i) установка и работа от непривилегированного пользователя без sudo; (ii) идемпотентность: повторный `install` поверх существующего HOME сохраняет `rev`/`last_hash` и не плодит инстансы; (iii) `nqctl uninstall` (+`--purge`) не оставляет процессов, лок-файлов и unit'ов; (iv) гонка старта: два одновременных запуска на одном HOME — ровно один жив; (v) HOME с пробелом и не-ASCII в пути; (vi) документированное поведение на NFS (flock ненадёжен) — либо отказ при старте с кодом 8; (vii) `nqctl doctor` как машинно-читаемый артефакт приёмки.
*Критерий:* каждый пункт — исполняемый тест или явная строка «не поддерживается, отказ с кодом N» в §8; `doctor --json` содержит все проверяемые поля.

## §10 — Рекомендации

**Вопрос 1 (профиль vs отдельный HOME): дефолт — профиль в одном HOME, но в виде §5-З‑5.1 (общий `lib/`, `instances/<name>/`).**
Обоснование: отдельный HOME — это N копий кода, N процедур обновления и неизбежный version skew между инстансами (а fsck/format_version у них общий — З‑6.8). Изоляцию данных доказывает тест (404/разные inode), а не раздельность каталогов. Отдельный HOME — когда инстансы принадлежат **разным UID** или разным трастам; это правило записать одной строкой, чтобы выбор был механическим: «разные UID или разные версии — разные HOME, иначе — профили».
*Критерий:* в §5 есть таблица «когда какой уровень»; дефолт в `nqctl instance create` — профиль; тест: два профиля, один `lib/`.

**Вопрос 2 (`/proc/nemeq` и T-01): переформулировать на `$NEMEQ_HOME`, `/proc` оставить только уровню (в) — и разделить тест надвое.**
Сейчас T-01 смешивает две разные вещи: иммутабельность образов (в новой раскладке — `lib/`) и runtime-каталог (в новой раскладке — `run/`). Предложение: T‑01a — `lib/` только для чтения, проверяется `chmod 0555` + запись от владельца → EACCES, без root; T‑01b — ro bind-mount/mount-ns, требует root, помечен `skipif not root`, относится к уровню (в). `/proc` из базовой приёмки убрать.
*Критерий:* T‑01a зелёный в CI без root; T‑01b скипается без root и проходит в root-джобе; в §8 нет критерия, требующего `/proc`.

**Вопрос 3 (формат поставки зависимостей): wheel-архив как источник истины + распаковка в `lib/pydeps` на install, с манифестом; предкомпилированные `.pyc` в поставке.**
Распакованный `lib/pydeps` «как есть» — плохо: нет манифеста целостности, нет атомарного апгрейда/откатa, невозможно ответить «какая версия стоит», и `.dist-info` легко теряется (ломается `importlib.metadata`). Wheel-архив рядом с дистрибутивом + `nqctl deps install --from wheelhouse/` (обычный zip-распаковщик, без pip), проверка sha256 по `wheelhouse/manifest.sha256`, сохранение `.dist-info`, генерация шимов в `bin/`. Это же готовит почву под Rust: `lib/pydeps` становится одним артефактом, который просто исчезает.
*Критерий:* `wheelhouse/` + `manifest.sha256` в поставке; `deps install` без сети, идемпотентен; `nqctl doctor` печатает версии всех пакетов из `.dist-info`; подмена одного байта в колесе → отказ с кодом 9; после установки `find lib -name __pycache__` пусто (pyc приехали с поставкой).
